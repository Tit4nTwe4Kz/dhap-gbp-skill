# DHAP GBP — run routine (shared, installed once per computer by run/install.sh or run/install.ps1)

The user's whole request is one line: **"Run DHAP GBP for [Dealership] [website]"**. Do everything below without asking them for anything else, except a missing website.

**Where things are.** REPO = the folder this file lives in, one level up (the user's local copy of `Clikdata2/dhap-gbp-skill`; usually `~/dhap-gbp-skill`, or `%USERPROFILE%\dhap-gbp-skill` on Windows). The **rules** live only in `REPO/SKILL.md`; this file is the **process**. Never work from memory or from an older copy.

## Procedure (every step, every run)
**0. Plan.** Keep a task list.

**1. Get the latest rules.** Make sure REPO is on `main` (`git -C REPO checkout main` if a branch is checked out), then run `git -C REPO pull --ff-only`. If it fails (no internet, local edits), say so and stop. Read ALL of `REPO/SKILL.md` and the top of `REPO/CHANGELOG.md`. Open your first reply with exactly `Using DHAP GBP v<REPO/VERSION>.`

**2. One-time tools check (silent when already done).** If `~/.dhap-gbp-venv` (Windows: `%USERPROFILE%\.dhap-gbp-venv`) is missing, create it: `bash REPO/run/scripts/setup_env.sh` on Mac; on Windows `python -m venv %USERPROFILE%\.dhap-gbp-venv` then `pip install -r REPO/engine/requirements.txt` and `python -m playwright install chromium` with that venv. Never repeat this once it exists.

**3. Business info.** The user gives only the dealership name and website. Read the city, state, street address and brand from the website and the Google listing (the website settles same-name dealers in different towns). Mitsubishi → MiDS, Jessica, RULE I. Any other brand → the NON-MITSUBISHI ADAPTATION section of SKILL.md. Ask only if the website is missing.

**4. Knowledge base — always read it.** Use the GHL integration's knowledge-base operations: list the sub-account's knowledge bases (the location comes from the connection), pick the one named "Mitsubishi CLIKsearch" (match the name with surrounding spaces trimmed) — if not exactly one match, stop and tell the user — then list all of its FAQs and check every program fact the report states against them (pricing, posts and photos per month, go-live, results figures and labels, start-up order, schema build). Do not skip this step or report it as unavailable while the GHL integration is connected; look for its tools first. Only when no GHL integration exists in the session, use the facts stated in SKILL.md and say so in the delivery message. Never write the knowledge base id or the location id into any page or file.

**5. Audit and record evidence** exactly as `REPO/run/references/evidence-capture.md`. Use **Claude in Chrome** (the user's signed-in Chrome), read-only, by default and without asking. Save a screenshot for every number, tile and stat card that will carry a popup (RULE K scope: top hero numbers on the DHAP Summary and AI Visibility, Alert tiles and stat cards), crop it to the claim, blur reviewer names, and crop out any account name, avatar or notification. Anything you cannot observe is "not recorded" — never guessed — and no overall score is published while evidence is incomplete. Optional checks run on their own when available: `engine/places.py` and `engine/jev.py` use the team key service (`DHAP_SERVICE_URL` + `DHAP_TEAM_CODE`) and skip quietly otherwise.

**5b. JEV decides (v15).** Put every yes/no text judgment into one items file and run `python3 REPO/engine/decide.py items.json` (kinds: `post_offer` and `post_event` for each post from the last 30 days; `delivery` for each delivery sentence from the collector and each "Offers delivery" label on the main or a department listing; `serving` for each serving sentence; `site_reviews` for each review sentence; `lookalike` for each look-alike candidate; `same_business` for each directory whose name the rule does not match — text "Website name: …\nDirectory listing name: …", rule answer from `python3 REPO/engine/directories.py evidence.json` — saved as `name_same` on that directory's reading). Each item carries the rule's answer (`areas.serving_rule`, the delivery patterns, the post-variety rule). Use the `final` answers in the evidence, save the whole ledger as `evidence.jev`, and copy every `review` line into the rep brief. Then: pull town names from the yes serving sentences (`areas.towns`), confirm each with `areas.confirm` (Google Places through the key service), parse the dealership's raw areaServed with `areas.schema_places`, and get `code_on_page` from `dhapFind([...])` in the same tab. Never decide these by hand when JEV is available.

**5a. NAP on every listing site (v15.2, rule 8; the website is the authority).** Record the website's name, address and Sales/Service/Parts numbers first, then run `python3 REPO/engine/listing_scan.py …` for the 7 automatic sites (one minute, one try each), read the 9 Chrome sites (Bing, Apple Maps, Yelp, Facebook, brand locator, CarGurus, Autotrader, Cars.com, DealerRater), and add a reading for each site the AI tools cited (at most the 5 most-cited domains not already checked) — skip any site that can't be read; never retry — exactly as `REPO/run/references/evidence-capture.md` §5 says. Department to department; toll-free never compared with local, and every toll-free business number on the website, its schema or the Google listing is flagged (it should always be local).

**5c. AI visibility check (v16.1, mandatory, every run).** Run `python3 REPO/run/scripts/ai_api_runner.py --city "<City>, <ST>" --dealer "<Dealer name>" --out <run>/ai` (check the keys first with `--check-keys`): it asks the 5 questions word for word — never the dealer's name or a brand — 5 times each on the 5 tools (ChatGPT, Gemini, Google AI, Claude, Brave) through their APIs, all at once, and keeps the first 2 businesses each answer names (`top2`), exactly as SKILL.md AI VISIBILITY CHECK and `REPO/run/references/evidence-capture.md` §7 say. A tool with no key is skipped and named: tell the user before scoring. Save every answer word for word, every business it names with its type, and whether it names the dealer into `evidence.ai_visibility`, then run `python3 REPO/engine/ai_visibility.py check evidence.json` until it says AI VISIBILITY OK. Never skip this step: without it the engine will not score.

**6. Score.** Write the evidence JSON (fields as `REPO/engine/examples/evidence-example-vacaville.json`; v15.2 replaces `nap.directories_agree` with `nap.site` {name, address, phone}, `nap.directories` (one saved reading per directory, rule 8) and `nap.postal_cities`; v15 adds `claimed.main_claim_link`, `claimed.lookalikes`, `nap.dept_phones`, `schema.areaserved` {delivery_offered, code_places, page_places, code_on_page}, `schema_rendered`, `jev`, `ai_visibility` (v16.0; it replaces `ai_answers`), and Google's age labels word for word as `newest_review_label` / `last_post_label`) and run `python3 REPO/engine/score.py score evidence.json --repo REPO`. Report edge warnings.

**7. Findings and wording** from evidence only (no review-markup finding, "Both views" for departments, evidence tags, competitor notes; the SKILL.md PURPOSE section decides what is said: get found / get chosen, Google-safe, only what CLIKsearch fixes, posts are "get chosen", Yelp as a finding, the schema as a value add the website company installs). Write the content JSON (as `REPO/reference/james-2026-10-20/content.json`, but from v15.2 without `alert.stats` and `alert.impact_para2`: the engine picks the dealer's four weakest areas for the stat cards and writes the Revenue Impact paragraph — rule 7; write the locked findings 06–08 from the next-weakest areas, checked with `python3 REPO/engine/alert_cards.py evidence.json`) with `"dhap_url": "REPLACE_WITH_DHAP_FUNNEL_LINK"` — the funnel link is always added by hand; never guess it.

**8. Build and check.**
- Mitsubishi dealers: `python3 REPO/engine/check_all.py --repo REPO --evidence evidence.json --content content.json --out OUT` (all seven gates must pass).
- Other brands: build from the templates per `REPO/run/references/build-guide.md` and the NON-MITSUBISHI ADAPTATION (pattern: `REPO/run/scripts/example_build_vacaville.py`), then run `REPO/run/scripts/run_assertions.py`, `probe_mobile.py` and `spellcheck.py` with the venv's Python; skip only the Mitsubishi-only suite lines and list each skip.
- **RULE K popups:** write the popup spec for the in-scope numbers, tiles and stat cards only, then run `REPO/scripts/proof_popup.py spec.json proof_dir --insert DHAP.html ALERT.html` (adds the block and the hint lines), then `REPO/scripts/check_proof_popups.py DHAP.html ALERT.html` with the venv's Python — it checks scope and taps every popup on 390 px and 360 px phones, and must say PASSED.

**9. Rep brief.** Write an internal `<dealership-name>_rep-brief_<MM-DD-YY>.md` (never sent to the dealer): the score in one breath with a one-line reason per category; what to lead with (proven findings) and what to credit; every judgment call explained in plain words with how to say it to the dealer; what changed since the last report (re-runs); what only appears after JavaScript (Google sees it, ChatGPT, Claude and Perplexity don't); the areaServed gaps both ways with talking points; look-alike listings; the Yelp rating AI tools show; the listing-site results and notes (`python3 REPO/engine/directories.py evidence.json`): every wrong listing with who must fix it (CLIKsearch's network: CLIKsearch; any other site: the dealer), every name sent to JEV or a person, and every department with no local number on the website (Sales first); the AI visibility results (`python3 REPO/engine/ai_visibility.py brief evidence.json`): the dealer's score and, for each question on each tool, the business AI named most and its type; every car-shopper site with no listing for the dealer and the closest retailer that site shows from the dealer's ZIP (from `directories.py`); every JEV review line; a note on any listing-site phone number that differs from the website (SKILL.md DIRECTOR'S CHECKS 5: may be a tracking number, inferred effect on AI visibility and local search, how to ask); honest answers to likely questions; what not to say; what was not checked. Never mention verification status: claimed (no "Claim this business") is what matters.

**10. Deliver.** File names (dealership name as given, lowercase, hyphens; audit date): `<name>_dhap_<MM-DD-YY>.html`, `<name>_health-alert_<MM-DD-YY>.html`, `audit_evidence_<name>_<MM-DD-YY>.md`, `<name>_rep-brief_<MM-DD-YY>.md`, `<name>_ai-answers_<MM-DD-YY>.xlsx` (`python3 REPO/engine/ai_visibility.py sheet evidence.json <file>`: one tab per AI tool, one row per answer). Send all five to the user. Finish with: score, status and what sets it; judgment calls; anything not observable; every departure from the locked spec (and why); anything unverified. Do not list the funnel link: it is always the placeholder `REPLACE_WITH_DHAP_FUNNEL_LINK` and is added by hand. Close the Chrome tabs you opened. Publish nothing unless asked.

**11. Rule changes** happen only by pull request to the repository. If you notice a rule problem, tell the user as a suggested repository change.
