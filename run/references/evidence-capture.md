# Evidence capture — how to record every item the rubric needs

The repository's SKILL.md ("Evidence capture (mandatory before scoring)") says what must be recorded. This file is HOW. Anything you cannot record is "not recorded": say so, never guess, and never publish a score that depends on it without telling the user.

## 0. Browser rules (Claude in Chrome — the user's signed-in Chrome, read-only)
- Load the tools in ONE ToolSearch call: `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__tabs_close_mcp,mcp__claude-in-chrome__find,mcp__claude-in-chrome__javascript_tool,mcp__claude-in-chrome__browser_batch`. Call `tabs_context_mcp {createIfEmpty:true}` first, work in your own tab, and **close every tab you opened before finishing**.
- Why Chrome and not the built-in browser: Google Maps shows a stripped "limited view" when signed out (no About tab, no Posts list, no photo dates, no review sorting). The signed-in view has them. 
- **Read-only.** Never click: "Claim/Own this business", "Suggest an edit", "Write a review", "Add photos", "Post", "Edit", "Sign in/out", cookie banners (leave them), or anything that changes a page. Typing is allowed only into search boxes (a ZIP in the Mitsubishi locator).
- Tool quirks: JS/`get_page_text` results are cut at roughly 700–2000 characters, so return compact lines. Output containing `?`, `=` or `&` in URLs can come back as `[BLOCKED: Cookie/query string data]`: `.replace(/[?=&]/g,'~')` before returning. `browser_batch` needs an explicit `tabId` on every action and an `actions` array. After `navigate`, wait 3–5 s. Closing a photo viewer with the X can close the whole gallery.
- Standing instruction (user, Oct 20 2026): use Chrome by default, without asking, for every check it can prove yes/no. Never assume, infer or guess a value (URL, path, phone, rating, status) that Chrome can confirm; if Chrome cannot prove it, record it as unverified. Still read-only: no claim/edit/post/publish clicks.

## 1. Website (all five key pages: home, About, Service, Parts, Directions)
1. Find the real URLs from the nav (`a[href]` list). "About Us" may point at /contactus. Directions may be /get-directions or "Hours & Directions".
2. Static fetch first: `curl -sL -A "<browser UA>" URL`. If it returns 403, fetch from inside Chrome (same origin, cookies): in a tab on the homepage run
   `const html=await fetch(path,{credentials:'include'}).then(r=>r.text()); const doc=new DOMParser().parseFromString(html,'text/html'); [...doc.querySelectorAll('script[type="application/ld+json"]')]` and parse each block.
3. Parse every block. Handle: top-level `@graph`, top-level arrays (each element carries its own `@context` — that is valid), `@id` references (a `department` list may only hold `{"@id":…}` pointing at entities elsewhere in the graph), and a bad `@context`/`url` (e.g. `google.com/url?q=…` pasted from Gmail = not valid schema.org).
4. Per entity record: @type, name, url, telephone, sameAs (classify each URL: Google Maps/`cid`, Facebook, Instagram, Yelp, other), areaServed (count + names), hasMap, map/maps, logo/image, description, openingHours(Specification), geo, makesOffer/hasOfferCatalog, aggregateRating/review (never a finding; if present flag as a RISK), department list (type, name, url, telephone, sameAs, map). Say "no hasMap" only for that property name; describe `map` separately.
5. Which department entities exist (Sales/Service/Parts) and what each links to (own page address? own phone distinct from the main number?). Record "Both views": website schema vs Google listings are two separate facts.
6. Record page text facts: header phones per department, hours, address; sitemap.html / nav / footer for any Reviews or Testimonials page.
7. **JavaScript check (v15, every run):** the schema collector reads each key page twice, raw (fetch) and after JavaScript (a hidden same-origin frame). Record `evidence_schema` as `schema` (scored) and `evidence_schema_rendered` as `schema_rendered`; list `js_only` in the rep brief. If a page's after-JavaScript reading fails, open that page in the tab and run the collector again. The collector also returns `area_served_raw` (the dealership's areaServed, raw) and `sentences` (serving, delivery and review sentences from the raw readable text) for JEV, and `dhapFind([...])` tells which code places appear in that text.
8. **Rendered reviews check** (browser, after scrolling to the bottom to let widgets load): `document.body.innerText` for `review|testimonial|stars?|rated`, plus review-looking iframes/widgets. Visible Google reviews on the dealer's own site earn the point; links that only send visitors out do not.

## 2. Google Search panel (do this BEFORE Maps — it shows things Maps hides)
`https://www.google.com/search?q=<Dealer+Name>+<City>+<ST>` → take a screenshot and `get_page_text`, then read the panel: rating + review count, **business description**, **"Departments:" line** (one link per department listing; a combined listing shows as one link), address, phone, hours (+ department hours), Profiles (Facebook link href), recent posts. The Departments line and the description are NOT visible on the Maps Overview/About tabs; missing them there is not evidence they are absent. Note an "Own this business?" link if shown (record it; do not click).

## 3. Google Maps — each listing (Sales, then the Service/Parts/combined listing)
- **Collector across pages (v14.9).** Paste `engine/collectors/maps_collect.min.js` once per Google tab; it saves itself in the page's storage. After every navigation run `eval(localStorage.__dhap + '\nwindow.dhapMaps = dhapMaps;'); await dhapMaps()`. Open a department listing by clicking its result link (`a[href*="/maps/place/Parts"]`) or by its exact place URL; never rebuild a place URL by hand. If the collector warns PANEL NOT LOADED, run it again on the place page.
- **Photo viewer:** advance with the on-screen arrows, not the keyboard (the viewer often ignores Right). The Latest category lists only recent uploads; post images count as photos, so read the posts list too.
URL pattern from a search: `https://www.google.com/maps/search/<Name>+<street address>+<city>` resolves straight to the place page. Place-page `/maps/place/.../data=!...!1s0x…:0x…` URLs can be reopened directly.
- **Overview** (`get_page_text`): categories (a GMB-categories line may be printed by an extension), address ("Located in: …" = nested), hours, website, appointment/booking link ("Open booking link"), "Services" link, phone, attributes line, "From the owner" post.
- **About tab** (click it, then `get_page_text`): attributes, service options, offerings → checklist items. A business description is NOT here (see §2).
- **Posts**: Overview → "See local posts" button, scroll the left panel 15 ticks twice, then parse dates (`Oct 8, 2026`, `16 hours ago`). Count posts dated inside the last 30 days, note the newest date, note variety (offer / event / call-to-action buttons: Learn more, Call now, View Offer, Sign up, Buy). A post with an image also counts as a photo.
- **Photos**: Overview → "Latest" (shows the newest age). Open the viewer and press `Right`, zooming the header (region ~[372,0,900,110]) each time: the header reads "Photo · Oct 2026" (month only). Count photos labelled with the current month inside the window; month-only labels from earlier months are not counted. Photo categories (Exterior / Inside / Workshop / By owner) give coverage; the first "By owner" photo header shows the profile avatar — a Mitsubishi/dealer logo = logo seen, a photo or an initial = logo not seen. Cover photo = the header image on the Overview.
- **Departments and claimed (rule 3):** read the main listing's "Departments:" line (Search panel). The main listing and every linked listing are the dealer's. Record whether the MAIN listing shows "Claim this business" (`claimed.main_claim_link`).
- **Department phones (rule 1):** for each department listing, record its Google phone and the website's phone for that same department (`nap.dept_phones`).
- **Delivery (rule 4 gate):** on the About tab of the main and each department listing, record Google's "Offers delivery" label word for word if shown (it becomes a JEV `delivery` item with rule answer yes).
- **Age labels (rule 2):** save Google's label for the newest review and the newest post word for word (`newest_review_label`, `last_post_label`); an exact post date may be saved as the date. Never type day counts by hand.
- **Reviews**: Reviews tab → Sort → "Newest" (menu item; Sort button ~(295,407) in a 0.6-scaled screenshot) → scroll the panel ~30 ticks → count exactly the 10 newest reviews, their ages, and how many have "Response from the owner". Newest review age feeds the recent-flow windows (Sales 15 d, Service 30 d, Parts 90 d).
- **Look-alike listings (rule 3 add-on):** run "[dealer] [city]", "[dealer] Parts [city]", "[dealer] Service [city]" and read "People also search for" on the main listing. Every listing with the dealer's name that is not the main listing or on its Departments line goes into `claimed.lookalikes` (name, address, phone, website, Claim link or not, where found) and becomes a JEV `lookalike` item.
- **Combined/separate department listings**: search `<Name> Service and Parts <street> Ste A`, `Mitsubishi parts department <city>`, `<Name> service`. A search that resolves straight to one place does not list the others; use "People also search for" and several differently-worded searches. Record every listing found, its category count, hours, phone, website, offerings, attributes, description (search panel), scheduling link, posts, photos, reviews (+owner replies).
- **Claimed**: record whether the main listing shows "Claim this business" (rule 3). That is what matters. Do not mention verification status anywhere (reports, rep brief, delivery message): nobody outside the account can see it.
- **Duplicates**: note any second listing for the dealership or its departments in Google, and on Yelp/Apple/etc.

## 4. Facebook
Open the page found in the Search panel Profiles (or `facebook.com/<slug>`). Record followers, category, address, phone, links, latest post date, and the rating: a star rating, a "% recommend", or nothing. Check the "More" tab menu — "Reviews given" is not the page's reviews. Rubric: star rating → compare within 0.5 of Google; percentage → drop the point and rescale (Reviews row); nothing shown → scored 0, not rescaled (judgment call; flag it).

## 5. NAP on every listing site (rule 8, v15.2) — the website is the authority
**First record the website** (`nap.site`): name, address and the Sales, Service and Parts numbers word for word (`phones`, null when the site shows none), and every telephone in its raw business schema (`schema_phones`: copy the schema collector's `schema_phones` output as is). **Then the Google listing's numbers** (`nap.google_phones`): Sales = the main listing, Service and Parts = their department listings (null when there is none). Toll-free anywhere is flagged — it should always be local. Every reading below is compared with it, department to department; toll-free numbers are never compared with local ones.
**The sites** are in `engine/listing_sites.json`, two scored groups: CLIKsearch's network (its 60+ list) and the AI and car-shopper sites. Every site whose method is `headless`, `chrome` or `site_search` gets one reading; add one `cited:<domain>` reading for each site the AI answer check saw a tool cite for this dealer.
1. **Automatic searches (7 sites, about a minute, no browser time):** `python3 engine/listing_scan.py --name "<Dealer>" --match "<words that identify it>" --city <City> --st <ST> --zip <ZIP> --phone <website Sales number> --out <run dir>`. Complete readings are accepted with their screenshot; only a reading marked `draft` needs a look (fill the missing part from its screenshot, set `dept` for a Service or Parts listing, remove `"draft"`). A `blocked` site is skipped — never retried, never re-read in Chrome.
2. **Chrome sites (9):** Bing, Apple Maps, Yelp, Facebook, the brand locator, CarGurus, Autotrader, Cars.com, DealerRater — open the `url`, or run the `find` web search and open the dealer's page on the site itself (never trust a search snippet). Copy name, address and phone word for word and crop a screenshot. One try each: a site that won't load or asks for a login is recorded `blocked` and skipped. (v16.0) A listing that shows no phone number is recorded `found` with `"phone": null` — it counts as not agreeing (incomplete listing). A listing that shows only the legal company name (LLC, Inc…) is recorded as read; the engine skips it. When a car-shopper site (CarGurus, Autotrader, Cars.com, DealerRater) has **no listing** for the dealer, search the site for the dealer's brand near the dealer's ZIP and record the closest retailer it shows: `"closest": {"name": …, "distance": "<as the site shows it, e.g. 11 mi>", "searched": "Mitsubishi near 14626"}`.
3. **AI-cited sites:** add a reading for each site the AI answer check saw a tool cite for this dealer — at most the 5 most-cited domains not already checked (MapQuest, Edmunds, TrueCar and CARFAX are checked only this way). Sites marked `skip` in the registry are never checked (login or bot walls, no public lookup, or the same data as a checked site).
4. **Each reading:** `{directory, status: "found", dept, name, address, phone, url, when, proof}`, or `{directory, status: "not_found", searched, url, when}`, or `{directory, status: "blocked", reason, url, when}` when even the signed-in Chrome is refused. Add the postal city names for the dealer's ZIP to `nap.postal_cities`. Never type `directories_agree`.
5. Run `python3 engine/directories.py evidence.json`: it shows each site's result, the two group scores, the names to send to JEV (`same_business`, saved as `name_same`) and the rep-brief notes (a department with no local number on the website).
The older five-directory steps below still describe how to read Apple Maps, Bing, Yelp, Facebook and the brand locator.
1. **Apple Maps**: `https://maps.apple.com/search?query=<Name>%20<City>%20<ST>` → `get_page_text` (phone, address, "Claim This Place" = unclaimed; a postal-name city such as Rochester for Greece counts as a match).
2. **Bing**: `https://www.bing.com/search?q=<Name>+<street>+<city>` → business card text (name, address, phone, ratings). Bing Maps pages render no text.
3. **Yelp**: `https://www.yelp.com/biz/<slug>` (link from the Search panel/Bing) → Claimed/Unclaimed, rating, phone, address. Record the rating and count as `reviews.yelp`: Apple Maps, Bing and Perplexity show this rating, not Google's (a finding and a rep brief talking point, never scored).
4. **Facebook** (from §4).
5. **Mitsubishi dealer locator**: (v14.9: the consent banner covers the bottom of the page — never click it; scroll the dealer detail panel up until Contact shows, or read the panel text with the page tools) `https://www.mitsubishicars.com/car-dealerships-near-me` → type the dealership ZIP in the zip box, Enter → click the dealer entry (click the list item, not only the link) → read the Contact phone and Sales/Service hours. A central-number mismatch counts as a mismatch and gets a finding.
Also open the dealer's page on Autotrader (and, when time allows, Cars.com, CarGurus, KBB, Carfax) on the site itself — never trust a search snippet — and add every phone number to the phone-number inventory (SKILL.md DIRECTOR'S CHECKS 5: a different number is a rep-brief note, not a score). Also note any other phone numbers seen (Yellow Pages …) in the phone-number inventory; they feed the "different local phone numbers" count. Some may be call-tracking numbers: say "not verified".

## 6. Record it
- Fill `evidence-example-vacaville.json`-style JSON (values only from the audit) → `python3 run/scripts/lib_dhap.py score evidence.json` (or `python3 engine/score.py score evidence.json`).
- Write the evidence record (.md) with: scores + working per row, phone inventory, the AI answer check table (`python3 engine/ai_answers.py brief evidence.json`), other checks, not-observable items and judgment calls, method + date. Anything not recorded is listed as such.

## 7. AI visibility check (v16.1, every run — mandatory)
SKILL.md AI VISIBILITY CHECK has the rule. Print the 7 questions for this dealer, word for word: `python3 engine/ai_visibility.py questions "<City>, <ST>"`. Never add the dealer's name or a brand to a question.
- **v16.1 (audits dated Oct 28 2026 or later): through the APIs.** `python3 run/scripts/ai_api_runner.py --city "<City>, <ST>" --dealer "<Dealer name>" --out <run>/ai` asks all 125 (5 questions × 5 runs × 5 tools: `chatgpt`, `gemini`, `google_ai`, `claude`, `brave`) at once and saves every answer (capped in length; the first names come first), its sources and `top2` — the first 2 businesses it names, in its order, pulled by Claude Haiku — to `<run>/ai/dhap_ai_<tool>.json`. Keys go in `~/.dhap-gbp-local/keys.env` or `run/scripts/keys.env` (copy `keys.env.example`, `chmod 600`, never commit it, never paste a key into chat); `--check-keys` lists what is set. Re-running the same command asks only what is missing. Then set each answer's `businesses` to its `top2` (at most 2; the engine refuses more) and `named` to whether this dealer is one of them and set `ai_visibility.method` to the line each record's `via` gives (API, model, location). No browser, no tabs.
- **v16.0 (Oct 27 2026 audits only) — where:** Claude in Chrome (same tab rules as §0). A new chat or a new search for every answer; never a follow-up; never sign in or out. Typing the question into the tool's own box is allowed (it is a search, not an edit). Ask each question **10 times on each tool**.
  | Tool (`tool`) | How |
  |---|---|
  | ChatGPT (`chatgpt`) | `https://chatgpt.com/?q=<question>&hints=search` (new chat, Search on; works signed out) |
  | Gemini (`gemini`) | `https://gemini.google.com/app` → type the question in a new chat |
  | Perplexity (`perplexity`) | `https://www.perplexity.ai/search?q=<question>` (may ask for a sign-in after a few questions: record blocked) |
  | Google AI (`google_ai`) | `https://www.google.com/search?q=<question>` → the AI Overview; if none shows, AI Mode: `https://www.google.com/search?q=<question>&udm=50` |
  | Claude (`claude`) | the run's own web search tool with the question word for word (Claude Code: WebSearch); the answer is written only from what it returns. `claude.ai` when the run has no search tool |
  | Microsoft Copilot (`copilot`) | Copilot Search, signed out: `https://www.bing.com/copilotsearch?q=<question>`; read the answer from a screenshot (zoom) when `get_page_text` returns nothing |
  | Brave (`brave`) | Ask Brave, signed out: `https://search.brave.com/ask?q=<question>` |
- **Wait for the full answer** (the stop or loading icon gone), then `get_page_text` (or the screenshot) and save the whole answer.
- **Record each answer** in `evidence.ai_visibility.answers` as `{tool, q, run, status: "answered", asked, when, answer, businesses, named}`:
  - `q`: the question id from `ai_visibility.py questions`; `run`: 1–10; `asked`: the question word for word.
  - `answer`: the full answer, word for word.
  - `businesses`: every business it names, as `{name, type}` — type one of dealership, oil_change, tire_shop, parts_store, repair_shop, retailer, other (add `brand` for a dealership when the answer gives it).
  - `named`: does the answer name this dealer (the right location, not a same-name dealer elsewhere).
  - A tool that will not answer within 60 seconds: `{tool, q, run, status: "blocked", asked, when, reason}` — move on; never retry.
- Set `ai_visibility.method` and `ai_visibility.city_st`, then run `python3 engine/ai_visibility.py check evidence.json` until it says AI VISIBILITY OK.
- Outputs: `python3 engine/ai_visibility.py brief evidence.json` (rep brief: who AI names most for each question on each tool) and `python3 engine/ai_visibility.py sheet evidence.json <name>_ai-answers_<MM-DD-YY>.xlsx` (one tab per tool, one row per answer).
